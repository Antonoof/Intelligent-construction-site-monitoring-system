# Методика «этап работ → необходимая техника»

ТЗ требует связывать технику на снимках с этапами графика «на основании сформированной участниками методики
(набора правил «этап работ → необходимая техника»)». Здесь эта методика целиком: как устроены правила, откуда они
взялись и как их менять. Методика — это данные, а не код: всё лежит в YAML, а движок (`backend/app/engine.py`)
применяет их одинаково к любому объекту.

| Файл | Что в нём |
|---|---|
| [equipment.yaml](equipment.yaml) | 14 классов техники: 8 из ТЗ + погрузчик, грейдер, башенный кран, буровая установка + план: бетононасос, асфальтоукладчик; синонимы для датасетов |
| [profiles.yaml](profiles.yaml) | 46 профилей техники — ядро методики |
| [assignments.yaml](assignments.yaml) | привязка видов работ справочника к профилям и стадиям S1–S5 |
| [rules.yaml](rules.yaml) | 10 правил отклонений, пороги, окна подтверждения, тексты предупреждений |
| [work_types.yaml](work_types.yaml), [work_types.md](work_types.md) | итог: 377 видов работ справочника с профилем, стадией и наблюдаемостью (генерируется) |
| [profiles_composite.yaml](profiles_composite.yaml) | 18 составных профилей для групп справочника (генерируется) |
| [Методика_этап_техника.xlsx](Методика_этап_техника.xlsx) | справочник организаторов + 9 столбцов методики, листы профилей, классов и правил |

Сборка и проверка: `python tools/build_methodology.py` — падает с понятной ошибкой, если виду работ не назначен
профиль или в профиле неизвестный класс техники.

## Как устроено правило

Вид работ справочника → **профиль техники** → проверки на снимках. Профиль отвечает на четыре вопроса:

1. **Какая техника обязательна.** Группы: «достаточно любого класса из списка» (`any_of`, `min`). У группы есть окно:
   `snapshot` — техника должна быть на каждом снимке, пока идёт этап; `shift` — хотя бы раз за смену
   (подвоз щебня, бетонирование захватками, доставка).
2. **Какая техника должна работать в паре.** Парное правило «ведущая → парная»: экскаватор без самосвала,
   миксер без насоса или крана, каток нужен после грейдера. Это пример из ТЗ, возведённый в правило.
3. **Какая техника допустима.** Вспомогательная техника, появление которой нормально.
4. **Насколько работы видны камере** — наблюдаемость:

| Наблюдаемость | Видов работ | Что проверяется |
|---|---:|---|
| высокая | 70 | работы ведёт тяжёлая техника на открытой площадке: нет техники — нет работ; проверка по каждому снимку |
| средняя | 99 | техника эпизодическая (подача, монтаж, доставка): нужна хотя бы раз за смену |
| низкая | 70 | техника вспомогательная: проверяется только «лишняя» техника |
| не видно с камер | 138 | работы внутри здания и документы: только «лишняя» тяжёлая техника |

Всё, что не входит в обязательную, парную и допустимую технику идущих в зоне этапов, — **техника, не
соответствующая этапу**. Башенный кран обслуживает всю площадку и лишним не бывает; грузовик и кран-манипулятор
(доставка) допустимы в любой зоне, где идут работы.

### Пример: «Устройство котлована» (12.3.1)

```yaml
EXCAVATION:
  observability: high
  required:
    - {role: разработка грунта, any_of: [excavator], min: 1, window: snapshot}
    - {role: вывоз грунта,      any_of: [dump_truck], min: 1, window: shift}
  companions:
    - lead: [excavator]
      partner: [dump_truck]
      message: Экскаватор работает без самосвалов — грунт не вывозится, возможно снижение темпа работ.
  allowed: [bulldozer, loader]
```

Экскаватор без самосвалов на снимке → «Неполный комплект техники», предварительно (1 снимок). Если так на трети и
более снимков дня (минимум 2 снимка) — отклонение подтверждено; если самосвалы не появились за день вовсе —
«Критично». Каток в котловане → «Техника не соответствует этапу»; если каток нужен этапу этой зоны, который
начнётся в ближайшие 3 недели, — «Опережение графика».

## Правила отклонений

| Код | Отклонение | Когда |
|---|---|---|
| NO_DATA | Нет данных | все снимки зоны непригодны: темно, туман, засветка, размыто — это «нет данных», а не «нет техники» |
| NO_EQUIPMENT | Работы не ведутся | этап с видимой техникой идёт по графику, а в зоне пусто (на серии — не меньше часа) |
| MISSING_REQUIRED | Нет необходимой техники | нет техники для обязательной роли профиля (выемка грунта, уплотнение…) |
| INCOMPLETE_SET | Неполный комплект техники | ведущая техника без парной на ≥ 30 % снимков — пример ТЗ |
| INSUFFICIENT_COUNT | Техники меньше плана | в графике «2 × автобетоносмеситель», а за день одновременно видно не больше одного |
| EARLY_START | Опережение графика | техника этапа зоны, который начнётся в пределах 21 дня |
| STAGE_OVERRUN | Этап не завершён в срок | техника этапа зоны, который закончился не раньше 30 дней назад |
| UNEXPECTED_EQUIPMENT | Техника не соответствует этапу | техника не нужна ни одному идущему этапу зоны |
| NO_ACTIVE_STAGE | Техника в зоне без работ | в зоне по графику ничего не идёт |
| STAGE_MISMATCH | Стадия по снимку не совпадает с планом | модель готовности (ML-часть) видит стадию раньше плановой |

Одно отклонение — на день, зону, этап, правило и класс техники; к нему прикладываются снимки-доказательства с
подсвеченными рамками. Отклонение по одному снимку — «предварительное», серия снимков делает его «подтверждённым».

### Как методика снижает число ложных предупреждений

- **Асимметричные пороги уверенности.** Для правил «лишняя техника» нужна уверенная рамка (≥ 0,5), а для правил
  «техники нет» засчитывается и сомнительная (≥ 0,3). Сомнительная рамка не создаёт тревоги ни в одну сторону.
- **Контроль качества до детекции.** Ночь, туман, засветка — «нет данных», зона не оценивается.
- **Окна подтверждения.** Самосвал мог уехать за грунтом на 10 минут: отклонение подтверждается серией снимков, а не
  одним кадром.
- **Техника, которую модель не видит, не требуется.** Бетононасос нужен бетонированию, но детектор его пока не
  распознаёт — требование видно в карточке этапа, а проверка ограничивается, пока класс не появится в модели.
  Когда модель v2 научится катку и грузовику, проверки с ними включатся без изменения методики.
- **Максимум по камерам.** Две камеры, видящие один экскаватор в одной зоне, дают один экскаватор, а не два.
- **Заявленная техника.** Башенный кран, который не попадает в кадр зоны, можно заявить на площадке — требования
  «нужен кран» им закрываются.

## Откуда взялись профили

- **Справочник организаторов** — 377 видов работ, 9 типов объектов, иерархия до 4 уровней. Строки без кода
  (подпункты) получили id вида `12.3.4-6`; в графике их можно писать и как `12.3.4.6`.
- **Технология работ**: котлован — экскаватор с самосвалами, основание — подвоз, распределение, уплотнение,
  монолит — кран подаёт арматуру и опалубку, бетон — миксер с насосом или краном и т. д.
- **Замечания экспертов из справочника** (столбец L) учтены явно:
  - «Монолитные работы ниже отметки 0» — «в целом как веха»: подпункты 12.3.9 контролируются одним профилем;
  - «Сложно отделять по фото с дальнего расстояния» (12.4.28-1…8) — у подпунктов низкая наблюдаемость;
  - «Если нет фото кровли, определить не получится» — кровля (12.4.31) не проверяется по технике;
  - «Важно разделять каждый этап работы фасада» — подэтапы фасада одинаковы по технике, поэтому разделяются
    визуально: стадия S4 по кадру общего плана (модель готовности из ML-части) и объекты Grounding DINO;
  - «На первых этапах не крит» (МАФ) — низкая наблюдаемость.
- **Группы справочника** (например, «12.3.4 Устройство фундамента») получили составной профиль — объединение
  техники подпунктов: если в графике только строка-группа, этап считается идущим, когда за смену видна техника
  любого подпункта. Если у строки графика есть подэтапы, проверяются подэтапы.

## Как изменить

- Поменять технику этапа — отредактировать профиль в `profiles.yaml` или назначение в `assignments.yaml`,
  затем `python tools/build_methodology.py`.
- Пороги, окна, тексты предупреждений — `rules.yaml`; версия правил пишется в каждое отклонение.
- Технику под конкретный проект задаёт сам график: столбец «Техника (план)» — «Экскаватор ×2; Самосвал ×3».
  Эта техника добавляется к профилю, а количество проверяется правилом «Техники меньше плана».
- Новый класс техники — добавить в `equipment.yaml` (с синонимами), дообучить детектор (`training/05–08`).
