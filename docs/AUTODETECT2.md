# AutoDetect2

Рабочее место разметчика для детекции строительной техники: авторазметка, поиск
выбросов в уже существующей разметке, активный отбор кадров, деление на train/val,
передача заданий напарнику и сборка кода обучения YOLO — в одном месте.

```bash
pip install -r requirements.txt
python app.py                 # http://127.0.0.1:8000
python app.py --port 9000 --reload
```

## Классы

Порядок — это id класса. Он вшит в каждый `.txt` с разметкой, поэтому менять его
задним числом нельзя; список задан в [`backend/config.py`](../autodetect2/backend/config.py)
и подставляется в новый проект по умолчанию.

| id | класс | id | класс |
|---|---|---|---|
| 0 | Dump truck | 5 | Bucket loader |
| 1 | Excavator | 6 | Mixer |
| 2 | Motor grader | 7 | Crane manipulator |
| 3 | Tower crane | 8 | Autocran |
| 4 | Bulldozer | 9 | Drilling rig |

Строка разметки с `class_id`, которого нет в списке, не расширяет проект до ста
классов — она попадает в отчёт проверки как `bad_class`.

## Что где лежит

Данные проектов — в `workspace/projects/<id>/` (`AUTODETECT2_WORKSPACE` меняет путь):
`project.json`, `state.json`, `data.yaml`, `train.yaml`, `index.json`, `cache/`,
`annotations/`, `assignments/`, `splits/`, `submissions/`, `models/`, `selections/`,
`exports/`.

Изображения и разметка остаются там, где лежали: AutoDetect2 индексирует пути, а
правки пишет в `annotations/` своего проекта. Исходная папка переписывается только
по явному флажку «писать и в исходную папку».

`workspace/` целиком в `.gitignore` — вместе с изображениями, весами и выгрузками.
Репозиторий клонируется за секунды и не тащит за собой датасет.

## Разделы

**Создание проекта.** Выбираются n папок, каждая помечается как train или val.
Папку можно указать на любом уровне: обход рекурсивный, ищутся `.jpg`, `.png`,
`.bmp`, `.webp`, `.tif`. Если в выбранной папке изображений нет, а во вложенных есть
(`images/train`, `images/val`), она автоматически разворачивается в отдельные
источники с угаданным split.

Для каждого изображения ищется YOLO-разметка: `…/labels/<stem>.txt` (зеркальный путь,
как в BDD — `images/train/x.jpg` → `labels/train/x.txt`), соседний `labels/` или файл
рядом. В карточке источника показано, у какой доли изображений разметка реально
нашлась, — на выборке в 200 файлов.

**Классы** задаются в отдельной карточке: кнопка «data.yaml» читает конфиг YOLO
(`names` списком или словарём, `nc`) и заодно подтягивает найденные на диске папки из
`train` / `val` / `test`, даже если в файле прописан чужой `path:`. Классы можно
добавлять, удалять и переименовывать — порядок это и есть id класса. Тот же редактор
есть на странице проекта, изменения уходят в `data.yaml`.

### Разметка

Диалог спрашивает бюджет — сколько изображений вы готовы разметить. Дальше работает
трёхшаговый отбор:

1. **Кластеры.** DINOv2-эмбеддинги → L2 → PCA-whitening (128D) → k-means на k групп
   (по умолчанию k = бюджету). Если в `workspace/reference/` (или в папке из
   `AUTODETECT2_REFERENCE`) лежит опорный кэш, векторы для знакомых имён берутся
   оттуда, а для остальных считаются локально и переносятся в то же пространство
   гребневой регрессией по якорям. Кэша нет — считается DINOv2, если есть GPU или
   изображений немного; иначе резервный дескриптор (тон, цветовые гистограммы,
   профиль градиентов). Что именно отработало, видно в поле `backend`.
2. **Интересы.** Если загружен `submission.csv`, для каждого изображения считаются
   уверенный FP (модель нашла бокс, GT нет), пропуск (GT есть, модель не увидела),
   боксы в полосе неуверенности и расхождение по количеству.
3. **Разнообразие.** Бюджет делится между кластерами пропорционально `√размер ×
   (1 + масса ошибок)`, внутри кластера идёт жадный отбор: максимум интереса при
   максимальном удалении от уже выбранного. Ползунок α смещает баланс.

Отбор можно сузить: только неразмеченные кадры, только размеченные (режим проверки)
или только те, у кого есть замечания. Кадры, отданные в задание напарнику,
исключаются всегда.

Очередь слева умеет работать и без отбора: **Отбор · Пустые · Проблемные · Все**.
«Проблемные» берутся из проверки разметки и отсортированы по тяжести замечаний,
а сами замечания показываются в правой колонке — не приходится гадать, что чинить.

**Редактор боксов** работает как в CVAT: ЛКМ по фону тащит изображение, ЛКМ по боксу
выделяет и двигает его, восемь маркеров (углы и рёбра) меняют размер, колесо
приближает к курсору, а при возврате к масштабу 1 картинка сама встаёт в исходное
положение. GT рисуется сплошной линией, предсказания — пунктиром, и те и другие в
цвете своего класса. Слои включаются кнопками `GT` и `Предсказания`; скрытая разметка
не ловит клики. Любое действие отменяется: `Ctrl+Z` и `Ctrl+Y`, история на 60 шагов.
Двойной клик по пунктиру переводит предсказание в разметку.

**Что ускоряет работу:**

| | |
|---|---|
| **Пусто** (`E`) | кадр без техники сохраняется пустым и сразу листается дальше — отрицательные примеры модели нужны не меньше положительных |
| **Как в пред.** (`Ctrl+D`) | разметка предыдущего кадра целиком; на стройке камера стоит месяцами, и соседний кадр — та же сцена десять минут спустя |
| **Похожим…** | те же боксы на k ближайших кадров в пространстве признаков; список соседей показывается до применения |
| **Спорный** (`R`) | кадр помечается и всплывает потом в разделе «Датасет» |
| Автосохранение | при переходе к следующему кадру, если правки не сохранены |
| Стрелки | двигают выделенный бокс; с `Shift` — меняют размер. Мышью попасть в край техники на краю кадра тяжело |
| `D` | дубль выделенного бокса |
| `1…9`, `0` | класс объекта, `0` — десятый |
| Темп | кадров в час и оценка оставшегося времени, по факту, а не по плану |
| `?` | полный список клавиш |

Правки пишутся в `annotations/`, а по флажку — и в исходную папку.

Кластеры везде называются именами в духе «Смешариков» — «Копатыч» запоминается,
а `k17` нет. Имя выводится из id, поэтому кластер зовётся одинаково на карте, в
очереди разметки и в дашборде.

### Проверка разметки

Отдельный раздел, который ищет не ошибки модели, а ошибки разметчика. Модель для
этого не нужна: большая часть брака видна из самих файлов.

| Проверка | Что ловит | Вес |
|---|---|---|
| `degenerate` | нулевая или отрицательная сторона | критично |
| `out_of_bounds` | бокс вылез за кадр глубже, чем на 0.4% | критично |
| `bad_class` | `class_id`, которого нет в `data.yaml` | критично |
| `duplicate` | один объект обведён дважды одним классом (IoU > 0.80) | критично |
| `class_conflict` | объект больше похож на другой класс | критично |
| `overlap` | два разных класса на одном объекте (IoU > 0.70) | средне |
| `nested` | маленький бокс целиком внутри большого | средне |
| `tiny` / `giant` | объект в несколько пикселей / бокс почти во весь кадр | средне |
| `aspect` | стороны как 12:1 и хуже | средне |
| `size_outlier` | площадь выбивается из своего класса | средне |
| `empty` / `rare_class` | пустой файл разметки, класс с единичными примерами | мелко |

`size_outlier` считается робастно: медиана и MAD по логарифму площади внутри класса,
порог по z-score. Среднее и сигма здесь не годятся — выбросы это ровно то, что мы
ищем, и они не должны участвовать в определении нормы.

`class_conflict` работает по виду объекта: каждый бокс вырезается, сводится к
дескриптору (тон, цвет, края), пространство whitening-ом приводится к 32D, у класса
берётся медианный центроид. Бокс, который ближе к чужому центроиду, чем к своему,
попадает в отчёт с подсказкой — на какой класс он похож.

У этой проверки есть предохранитель. Перед тем как доверять ей, считается доля
боксов, чей ближайший центроид — свой же класс. Если она не отличается от случайного
угадывания, сигнала в дескрипторе нет, проверка молчит целиком, и `backend` в отчёте
говорит почему. Без этого на датасете, где классы неразличимы по цвету и форме,
«похоже, класс перепутан» посыпалось бы на половину кадров — и весь отчёт пришлось бы
выбросить. Сверх того, результат обрезается до 5% боксов с наибольшим запасом:
разбирать четверть датасета никто не станет, а первые полсотни — станет.

Клик по кадру открывает полноразмерный редактор поверх списка. Кнопка «В задание
напарнику» превращает текущий фильтр в задание.

### Датасет

**Деление train / val.** Долей или числом кадров, с тремя настройками:

- **Группировка.** `obj53359_photo2023-07_03` и `obj53359_photo2023-07_04` — это
  один и тот же вид с разницей в минуту. Если такие кадры разъедутся между train и
  val, метрика окажется завышенной, а на новых объектах модель провалится. По
  умолчанию группировка идёт по префиксу имени; можно по папке или отключить.
  Отключённую группировку интерфейс подсвечивает и считает риск утечки.
- **Выравнивание классов.** Итеративная стратификация: сначала раздаются группы с
  самыми редкими классами. Если оставить их на потом, редкий класс целиком окажется
  в одной половине и метрика по нему станет лотереей.
- **seed** — чтобы деление воспроизводилось.

Кнопка «План» показывает результат до применения: полосу train/val, число групп и
таблицу по классам с подсветкой перекосов. Заказанная доля и полученная различаются
тем сильнее, чем крупнее группы, — на шести съёмках по двадцать кадров точнее, чем
кратно ⅙, не выйдет, и интерфейс показывает, что получилось на самом деле.

Применение проставляет `split` каждому кадру и переключает `data.yaml` на списки
файлов `splits/train.txt` и `splits/val.txt`. Список путей вместо пары папок —
единственный способ описать произвольное деление: после стратификации train и val
перемешаны внутри одних и тех же каталогов. Ultralytics читает такие списки наравне
с папками.

**Выгрузка в YOLO** собирает каноническую структуру `images/{train,val}`,
`labels/{train,val}` и `data.yaml`. По умолчанию — жёсткие ссылки: копия датасета на
4 ГБ ради смены раскладки папок это потерянное место и полчаса ожидания, а ссылка
занимает байты. На другой том ссылка не ляжет — тогда файл копируется.

**Предразметка моделью.** Любая подключённая `*.pt` прогоняется по неразмеченным
кадрам, и её боксы появляются в редакторе пунктиром — дальше их правят, а не рисуют
с нуля. Кнопка «Принять в разметку» превращает черновик в настоящие `.txt`, но
только там, где разметки ещё нет: перезаписать ручную работу автоматическим
черновиком — самый дорогой способ потерять день.

### Задания напарнику

Задача: раздать работу на двоих и не разметить одно и то же дважды. Решается без
сервера, файлами.

1. **Создать задание** — берутся кадры без разметки, кадры с замечаниями, последняя
   выборка или просто свободные. Всё, что уже отдано в другое задание или закрыто,
   из кандидатов исключается. Кадры равномерно разрежаются по списку: подряд идут
   снимки одной съёмки, и напарник получил бы один и тот же вид.
2. Кадры переходят в состояние **«в ожидании»** и пропадают из вашей очереди, из
   отбора и из кандидатов на следующее задание.
3. **Экспорт** — на выбор:
   - `*.adtask.json` — имена кадров, текущие боксы и классы. Килобайты, годится,
     когда изображения у обоих одни и те же (общий диск, одна папка);
   - `*.zip` — плюс сами изображения, `labels/`, `data.yaml` и README. Такой архив
     открывается и как YOLO-датасет: CVAT, LabelImg и Roboflow прочитают его без
     подготовки.
4. Напарник жмёт **«Принять задание»**: совпавшие по имени кадры складываются в
   очередь разметки, как обычная выборка. Из архива на чужой машине сначала делается
   проект по распакованной папке `images/`.
5. **«Собрать результат»** отдаёт `*.result.json`, который на вашей стороне
   вливается кнопкой **«Импортировать результат»**. Принимается и `*.result.json`,
   и zip с папкой `labels/`, и просто папка с `*.txt` из чужого инструмента —
   сопоставление везде по имени файла без расширения.
6. Задание закрывается, кадры переходят в «готово», кэши метрик сбрасываются.

**«Отозвать»** возвращает кадры в работу, если напарник передумал.

### Карта данных (heatmap)

Настоящее тепловое поле над 2D-проекцией: точки раскладываются по сетке и
размываются гауссианом. Каждый режим, кроме плотности, — это **доля**: числитель это
то, что пошло не так, знаменатель — сколько всего могло пойти не так в этой области.

- **Ошибки** — (FP + пропуски) / (объекты + предсказания)
- **Пропуски** — пропуски / размеченные объекты, то есть 1 − recall
- **Ложные** — боксы в пустом месте / размеченные объекты
- **Рамки** — сползшие рамки (IoU < 0.5 на реальном объекте) / все предсказания
- **Интерес** и **Неуверенность** — среднее по изображениям области
- **Плотность** — просто число изображений

«Ложные» и «Рамки» разделены намеренно. Две трети несовпавших боксов — это найденный
объект с неточной рамкой, а не выдумка модели; пока они считались вместе, в топ
«ложных» попадали кадры, где модель просто почти ничего не нашла.

Считать ошибки штуками бесполезно: улица с шестьюдесятью машинами теряет больше
объектов, чем пустая дорога, что бы модель ни делала, — и карта ошибок вырождается в
карту плотности. Агрегация идёт как отношение сумм по ячейке, а не среднее из
отношений по изображениям: иначе кадр с одним объектом весил бы столько же, сколько
кадр с шестьюдесятью. Значения по кадрам сглажены псевдосчётчиками к глобальной
доле: один неверный бокс из одного — это формально 100%.

Ячейки, под которыми слишком мало данных, не закрашиваются. Ползунок порога работает
**по квантилям**: «0.5» означает «скрыть более холодную половину», и всё, что выше
порога, растягивается заново. Кнопка «Разметить» открывает полноразмерный редактор
прямо поверх карты — уходить со страницы и терять зум не нужно.

### Обучение

Выбор архитектуры (YOLO 8 / 11 / 12 / 26) и размера (n, m, l, x), одиночная модель
или ансамбль со своим imgsz, полный набор параметров ultralytics. Кнопка собирает
`AutoFile.zip`: `train.py`, `predict.py`, `data.yaml`, `train.yaml` и README.
На сервере:

```bash
pip install -r requirements.txt
python train.py --dataset-root /path/to/dataset
```

Результат — `result/best_<i>.pt` и `submission.csv` по всем данным.

### Загрузить результаты

Приём `submission.csv` — drag & drop, выбор файла или путь на диске. Распознаются три
раскладки: `x_center/y_center/width/height`, `x_min/y_min/x_max/y_max` и упакованная
колонка `prediction` (`cls conf xc yc w h …`), в нормированных или пиксельных
координатах.

Выгрузки часто содержат разметку и предсказания в одном файле, различая их колонкой
`source` (`gt` / `pred`). Строки разметки отбрасываются: если посчитать их
предсказаниями, модель «угадает» каждый бокс и метрики потеряют смысл. Так же
отбрасываются строки-заглушки без координат (`class_id = -1`).

Разобранный файл кладётся в `cache/submission.npz` одним блоком массивов: повторные
обращения читают его за доли секунды вместо повторного разбора CSV. То же сделано
для разметки — `cache/ground_truth.npz`.

### Статистика

Считается фоновой задачей с пошаговым прогрессом: mAP@50 и mAP@50:95 (101-точечная
интерполяция), precision / recall / F1, кривая по порогу уверенности, AP по классам,
mAP по кластерам, разбор типов ошибок, распределения уверенности и размеров боксов,
худшие изображения. Сопоставление боксов делается один раз по всем предсказаниям —
пороги применяются поверх, поэтому кривая точная.

### Инференс

Подключение n моделей `*.pt` (загрузка или поиск по диску), отбор k максимально
разнородных изображений валидации (жадный k-center по эмбеддингам) и Optuna по conf
каждой модели, `wbf_iou` и `skip_box_thr`. Модели прогоняются один раз, а каждая
проба перебирает только WBF по кэшу боксов — поэтому сотня проб занимает секунды.
Итог — `AutoFile_infer.zip` с `infer.py` и `wbf_params.json`.

## Формат submission.csv

```csv
image_id,class_id,confidence,x_center,y_center,width,height
train_000.jpg,0,0.87,0.512,0.463,0.104,0.221
```

Координаты нормированы. Именно такой файл генерируют `predict.py` и `infer.py` из
бандлов, и он же загружается обратно в приложение. `image_id` можно писать без
расширения — сопоставление идёт по имени файла.
