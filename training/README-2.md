# Обучение и предсказание

Две модели ML-части:

- **Детектор техники** — RF-DETR Large. Версия v1 (10 классов, mAP50 0,907) обучена командой; версия v2 добавляет
  **каток и грузовик** из перечня ТЗ по открытым датасетам из ссылок организаторов (шаги 5–8).
- **Готовность и стадия** — замороженные DINOv2 ViT-g (сцена) и RF-DETR (техника) + обучаемая голова: по кадру общего
  плана она выдаёт готовность объекта 0–100 % и стадию S1–S5 (шаги 0–4).

Все команды запускаются из корня репозитория.

## Установка

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   # GPU
# pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu   # ноутбук без GPU
pip install -r training/requirements.txt            # шаги 0–4: готовность и стадия
pip install -r training/requirements-detector.txt   # шаги 5–8: детектор v2 и экспорт для CPU
```

Веса детектора v1 положите в `weights/rfdetr_large_best_ema.pth`, таймлапсы — в `videos for train/`.

| 7 | `python training/07_eval_conditions.py` | минуты | `docs/metrics_detector_v2.md` — AP50 по классам и условиям съёмки |
| 8 | `python training/08_export_cpu.py` | минуты | `weights/rfdetr_v2.onnx` для ноутбуков без GPU + замер скорости |

```bash
python training/03_predict.py "videos for train/video3.mp4" --every 3   # кадр каждые 3 с видео
python training/03_predict.py photo.jpg --expected 0.6                  # своё фото, план 60%
python training/03_predict.py --no-vlm --no-openvocab                   # быстро: без Grounding DINO и Qwen3-VL
```

**Модель готовности в сервисе — только инференс.** Из `training/runs/<прогон>/` сервису нужны `head.pt`,
`train_embed.npy` и столбцы видео/готовность/стадия из `train_predictions.csv` — они лежат в
`weights/readiness/<прогон>/` ([weights/README.md](../weights/README.md)). Конвейер кадра
`backend/app/ai/readiness.py` повторяет `stage_perception` из `03_predict.py` (DINOv2 → сетка 9×16 → голова), признаки
техники берутся из рамок RF-DETR, уже сохранённых для снимка; тест сверяет их с `common.det_features`. Qwen3-VL 8B в
сервисе заменяет VLM, которая помещается в память сервера (8B → 4B → 2B → SmolVLM2-500M), а проверку Claude — YandexGPT.

## Детектор v2: классы ТЗ

ТЗ перечисляет технику, которая может встретиться: самосвал, экскаватор, каток, кран-манипулятор, бетоносмеситель,
бульдозер, грузовик, автокран. Детектор v1 знает шесть из них и ещё четыре класса (погрузчик, грейдер, башенный кран,
буровая установка). Катка и грузовика в v1 нет — их даёт датасет №1 из ссылок организаторов.

| Класс ОКО | ТЗ | v1 | Источники разметки v2 |
|---|:---:|:---:|---|
| экскаватор | ✓ | ✓ | ds1 Excavator, ds3 (223 снимка), ds5 excavator-crane, smalldigger |
| самосвал | ✓ | ✓ | ds1 Dump truck |
| **каток** | ✓ | — | ds1 Roller, ds5 roller |
| кран-манипулятор | ✓ | ✓ | ds1 Crane manipulator |
| автобетоносмеситель | ✓ | ✓ | ds1 Mixer, ds5 concrete truck |
| бульдозер | ✓ | ✓ | ds1 Bulldozer |
| **грузовик** | ✓ | — | ds1 Truck, Trailer, Gazelle, Tanker |
| автокран | ✓ | ✓ | ds1 Autocran |
| погрузчик | | ✓ | ds1 Bucket loader Big / Standart, Forklift Standart / Giraffe |
| грейдер | | ✓ | ds1 Motor grader |
| башенный кран, буровая установка | | ✓ | данные v1 команды |
| автобетононасос (v3) | | — | ds5 pump-truck — мало снимков, нужна доразметка |

| id | Ссылка | Формат | Лицензия |
|---|---|---|---|
| ds1 | kaggle.com/datasets/xyzyxzzxy/construction-equipment | YOLO, 17 классов, ~17 ГБ | CC0 |
| ds2 | kaggle.com/datasets/kartaviychert/arh-df | YOLO, ~430 МБ | GPL 2 |
| ds3 | github.com/miniexcav/Construction-Machines-Images-Dataset | YOLO, 223 экскаватора | только исследования |

| ds5 | universe.roboflow.com/jejung/construction-machinery-tbosw | COCO, 78 снимков, 24 класса | CC BY 4.0 |

Скрипт 5 читает YOLO, COCO и VOC в любой структуре папок, приводит имена классов к классам ОКО по синонимам
(`methodology/equipment.yaml`), убирает дубликаты между источниками (SHA-256 и перцептивный хеш) и сохраняет датасет в
формате COCO, который RF-DETR принимает без конвертации. Скрипт 6 стартует с весов v1: признаки техники уже выучены,
голову RF-DETR переинициализирует под новое число классов сам.

### Своя тестовая выборка

Отдельный тестовый набор организаторы не дают, его надо собрать самостоятельно с учётом освещённости, сезонности и
видов техники (ТЗ, раздел 6.2). Скрипт 5 размечает каждый снимок по условиям съёмки и делит данные со стратификацией
по классу и освещённости:

| Метка | Как определяется |
|---|---|
| `day` / `dusk` / `night` | средняя яркость кадра |
| `winter` | доля ярких малонасыщенных пикселей в нижней половине кадра (снег) |
| `far` / `near` | самая крупная рамка на снимке меньше или больше 1 % кадра (общий план или зональная камера) |

Скрипт 7 считает AP50, точность и полноту по каждому классу — в целом и отдельно для каждого условия. Метрики v2
появятся после обучения; в документации приведены только метрики v1 из ML-части.

## Ноутбук без GPU

ТЗ требует демонстрации на стандартных компьютерах. Варианты:

- **Сервис без детектора** — правила, API и интерфейс работают на любом CPU; демо-проекты идут с эталонной разметкой.
- **RF-DETR на CPU через ONNX Runtime** — шаг 8 экспортирует модель, сервис запускается с `OKO_DETECTOR=onnx`;
  PyTorch не нужен. Замер скорости на своём ноутбуке печатает тот же скрипт.
- **RF-DETR на CPU через PyTorch** — `OKO_DETECTOR=rfdetr OKO_DEVICE=cpu`.
- Для слабых ноутбуков — вариант RF-DETR Small или Medium: те же скрипты 6–8 с `RFDETRSmall` вместо `RFDETRLarge`.

Модель готовности на DINOv2 ViT-g в CPU-режиме не используется: кадр общего плана оценивается на AI-сервисе с GPU
или энкодер заменяется на DINOv2 ViT-S/B (`backbone.name` в `config.yaml`) с переобучением головы — это минута.

### Статус

- **Энкодер сцены — DINOv2 ViT-g** с открытыми весами; DINOv3 подключается одной строкой в `config.yaml` (`backbone.name`).
- **OCR даты пока не дообучен.** EasyOCR читает дату не на всех камерах; сервис берёт время снимка из поля
  загрузки, EXIF или имени файла, поэтому OCR — запасной источник.
- **Следующие шаги:** дообучить RF-DETR на общих планах с высоты (башенные краны, бетононасосы) по разметке из
  проверки и из вердиктов «ложное срабатывание» в сервисе; класс «бетононасос» (v3); реальные плановые даты этапов
  из графика вместо доли срока.

## Требования к оборудованию

| | Весь ML-пайплайн | без Qwen3-VL (`--no-vlm`) | сервис ОКО с детектором в ONNX |
|---|---|---|---|
| **GPU** | NVIDIA 24 ГБ: RTX 3090 / 4090, A5000, L4 | NVIDIA 8 ГБ: RTX 3060 Ti / 4060 и выше | не нужен |
| **Оперативная память** | 32 ГБ | 16 ГБ | 8 ГБ |
| **Диск** | 35 ГБ свободно | 15 ГБ свободно | 2 ГБ |
| **ПО** | драйвер NVIDIA ≥ 570 (CUDA 12.8), Python 3.10+, Windows или Linux | то же | Python 3.10+ или Docker |

## Настройки — `config.yaml`

- `stages` — границы стадий как доли готовности; `videos.<файл>.stage_until` — свои границы для видео.
- `videos.<файл>.plan_finish`, `total_days` — план стройки: `plan_finish: 0.8` значит «по плану закончить к 80% срока».
- `backbone.name` — энкодер сцены. По умолчанию `facebook/dinov2-giant`, поддерживается и DINOv3 (`facebook/dinov3-*`).
- `detector.tiles`, `videos.<файл>.tiles` — детекция техники по фрагментам кадра для общих планов с высоты.
- `head.holdout_video` — видео, которое не участвует в обучении.
